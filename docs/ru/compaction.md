# Контракт компакции

> Аудитория: все, кто меняет `runtime/context/`, или подключает ядро к модели,
> окно которой длинный запуск перерастает.
> Код: `runtime/context/manager.py` (проход), `runtime/context/compaction.py`
> (уровни и пол), `runtime/context/carrier.py` (что такое выжимка),
> `runtime/context/ledger.py` (что переносится кодом),
> `runtime/turn_policies/compaction.py` и `runtime/query.py` (гейты).

Длинный запуск перерастает своё окно. Компакция — то, что позволяет ему
продолжаться: она убирает из промпта самую старую часть транскрипта и
оставляет на её месте что-то меньшее. Эта страница формулирует, что компакция
гарантирует — в терминах, которые может проверить тест, — и зачем нужен каждый
пункт. За каждым пунктом стоит сбой, случившийся в реальной долгой сессии.

## Словарь

| Термин | Значение |
|---|---|
| окно `W` | `model_context_window`, окно контекста провайдера в токенах |
| промпт `P` | весь запрос: история **плюс** системный промпт и определения инструментов (*накладные расходы*), в откалиброванных токенах |
| триггер `T` | `compaction_trigger_tokens` (см. [Арифметику бюджета](#арифметика-бюджета)); проход открывается при `P > T` |
| цель `R` | куда целится открытый проход; `R < T` |
| проход | один прогон каскада ниже, открытый гейтом |
| отрезок | то, за что отвечает одна выжимка: один или несколько соседних блоков вызова инструмента с ответами |
| носитель | текст, заменяющий отрезок: выжимка, свёртка или сводка пола |
| реестр | единственное сообщение, которое выносит точные значения из сжатых отрезков; пишет его код |
| защищённое множество | то, что не может убрать ни один уровень (см. [инвариант 10](#10-что-не-убирается-никогда)) |

## Инварианты

### 1. Прогресс

Каждый открытый проход заканчивается с `P ≤ T` или на **полу**: вне
защищённого множества убирать больше нечего. Проход, который ничего не мог бы
изменить, не открывается вовсе. Ни один запуск не падает из-за того, что
компакция «не продвинулась», и ни один гейт не срабатывает на каждой итерации.

*Почему.* Запуск на истории из сотен коротких раундов при большой поверхности
инструментов открывал проход на каждой итерации, освобождал по 0–3 токена и
упал на бюджете повторов после 75 проходов. Гейт мерил весь промпт; проходы
могли уменьшать только историю, и ни одному уровню не было что взять.

Бюджет повторов (`compaction_failed_max_retries`) остаётся только для случая,
где пол не поможет: история уже на полу, и какой-то уровень бросил исключение.
Проактивный проход, исчерпавший его, приостанавливает уровни с суммаризатором
на ограниченный срок (маскирование и пол продолжают работать); реактивный
передаёт ход лестнице уменьшения выходного лимита и валит запуск только когда
лимит уменьшать некуда — единственная ситуация, в которой историю невозможно
вместить.

### 2. Порядок уровней

Проход идёт от дешёвого к дорогому и только пока промпт выше цели:

1. **Маскирование** (`run_tier1_truncation`). Выводы инструментов вне
   сохраняемого хвоста заменяются заглушкой: любой вывод размером не меньше
   `tool_result_truncation_ratio × W` и — от старых к новым, пока цель не
   достигнута — любой вывод старше `compaction_mask_keep_recent_results`
   последних и длиной не меньше `compaction_mask_min_tokens`. Модели не
   требует и отказать из-за её отсутствия не может.
2. **Суммаризация** (`run_tier2_summarisation`, затем `run_tier3_fold`).
   Самые старые отрезки заменяются выжимкой модели; затем серии старых выжимок
   и старых реплик оператора сворачиваются в одну свёртку, которую позже может
   поглотить следующая.
3. **Пол** (`run_floor`). Если промпт всё ещё выше триггера (выше цели для
   принудительного прохода — после отказа провайдера или при оценке за
   аварийной чертой), убираются самые старые отрезки, сырые раньше выжимок,
   пока цель не достигнута или убирать больше нечего. На их месте остаётся
   одна сводка, написанная кодом.

Выжимка — улучшение по сравнению с полом, но никогда не условие прогресса.

### 3. Неудавшаяся или отсутствующая выжимка — нормальный исход

Вызов суммаризатора заканчивается одним из: выжимка, `transport` (провайдер
бросил исключение), `timeout` (нет ответа за
`compaction_summary_timeout_seconds`), `empty` (нет пригодного текста),
`too_large` (запрос не помещается в окно суммаризатора) или `not_smaller`
(выжимка не меньше отрезка). Ни один из них не валит проход: отрезок
остаётся, и пол заберёт его, если место нужно. Против отрезка засчитываются
только `empty` и `too_large`
(`compaction_summary_failed_unit_max_attempts`), потому что только они
повторяются.

**Вход суммаризатора ограничен по построению** величиной
`min(compaction_summariser_input_max_tokens, W / 4)`: отрезок больше этого
показывается с выводами инструментов, урезанными до первых и последних
строк, и никогда не посреди строки. По умолчанию суммаризатор — та же модель,
что только что отказала в запросе как в слишком длинном; её вход обязан
поместиться.

### 4. Факты — из состояния, а не из модели

Точные значения переносит код, в **реестре**, а не суммаризатор. Всякий раз,
убирая что-то из окна, уровень сначала записывает из уходящих сообщений:

- указания оператора дословно (обрезанные по границе строки);
- файлы, которые агент прочитал, записал или отредактировал, — по
  объявленной роли инструмента;
- идентификаторы и точные значения узнаваемой формы — URL, UUID, пути, хэши,
  временные метки, версии, пары `host:port`, хэндлы, токены вида
  идентификатора — каждый вместе со строкой, в которой стоял;
- упавшие вызовы инструментов с первой строкой их сообщения;
- последний записанный агентом план и заданные им вопросы.

Реестр — одно сообщение роли user с меткой `protocore.compaction_ledger`; его
метаданные хранят собственное структурированное состояние, и каждый проход
пересобирает реестр из этого состояния и того, что проход убрал. Суммаризатору
он **никогда** не показывается — запись, которую модель переписывает при
каждой свёртке, накапливает ошибки, — и ни один уровень его не сжимает.
Значения шумной формы (временные метки, голые числа, хэши) берутся только из
реплик оператора, собственного текста и аргументов агента и из *отличительных
строк* вывода инструмента — строк, форма которых, без учёта чисел, в выводе не
повторяется. Лог в тысячу строк называет свою настройку, ошибку или результат
один раз; эта строка и сохраняется.

Чего реестр не делает: не узнаёт значения без формы. Количество с единицей
измерения или имя остаются задачей выжимки.

### 5. Носитель

Выжимка — это **обычный текст под пятью фиксированными заголовками**:
`## Progress`, `## Facts and values`, `## Decisions and constraints`,
`## Failures`, `## Open`. Она запрашивается через
`ILLMProvider.complete_text` — никогда под схемой ответа — и читается терпимо
функцией `read_carrier`:

- блоки рассуждений и ограждения кода удаляются;
- JSON-обёртка, которую модель всё же написала, разворачивается — целая или
  незакрытая;
- ответ без заголовков сохраняется под `## Notes`;
- ответ, обрезанный выходным лимитом, теряет последнюю незаконченную строку, а
  не всё остальное;
- каждый раздел урезается до своей доли бюджета по границам строк — одна
  чрезмерно длинная строка по границе слова, — поэтому длинный рассказ о
  ходе работы не может вытеснить точные значения.

*Почему.* Одна JSON-строка `summary` с потолком в 1 024 символа теряла
дословные идентификаторы на каждой модели, на которой её измеряли, а обычный
текст под заголовками с достаточным бюджетом их сохранял. И запрос по схеме —
единственный запрос, который может вернуться ошибкой разбора: объект, который
модель не закрыла, проза вместо объекта. У текста под заголовками способа
оказаться некорректным нет.

### 6. Инструкции суммаризатора — не слова пользователя

Инструкция — **системное** сообщение; материал отгорожен как данные в
сообщении пользователя (`<transcript>…</transcript>`); любое предложение
инструкции, повторённое в ответе, удаляется; и каждый носитель начинается со
строки о том, что его написала среда выполнения, а не пользователь, и что
это справка, а не указание. Выжимку, пронёсшую дальше повелительную фразу
самого компактора, видели приписанной пользователю — после чего запуск
перестал действовать.

### 7. Повторная подача

Системный промпт и определения инструментов собираются заново для каждого
запроса, поэтому компакция их никогда не трогает. Реестр возвращается после
каждого прохода на границу между сжатым прошлым и сохранённым настоящим и
перечисляет затронутые файлы, начиная с последних, — агент знает, что
перечитать, вместо того чтобы доверять выжимке их содержимого.

### 8. Гейт

Гейт мерит весь промпт — историю плюс системный промпт и инструменты, которые
нёс последний запрос, — против триггера, который и так стоит ниже окна за
вычетом выходного резерва (см. ниже). Открытый проход целится в
`R = compaction_target_ratio × min(T, P)`, поэтому следующий проход наступит
через много ходов, а не через один. Проход, освободивший меньше
`compaction_min_gain_ratio`, откладывает гейт на каждой итерации на
`compaction_no_gain_backoff_iterations`.

### 9. Обратимость

Не теряется ничего, что нельзя найти снова. Замаскированный вывод оставляет
заглушку с именем инструмента, размером и ссылкой на blob с оригиналом.
Выжимка, свёртка или сводка пола называет blob с сообщениями, которые она
заменила. Хост, ведущий собственный долговременный транскрипт (а большинство
ведут), — вторая копия.

### 10. Что не убирается никогда

Первая реплика пользователя в запуске (задача), реестр, замороженные
справочные блоки (маскирование может убрать их в blob),
`compaction_keep_recent_turns` последних сообщений (одно — после отказа
провайдера) и пакет результатов инструментов, который модель ещё не прочла.
Вне реактивного восстановления реплики, перенесённые из прежнего запуска, не
трогаются; реактивное восстановление может их сжать, но никогда в одном
отрезке с репликами текущего запуска, и каждая замена сохраняет метку
переноса. Реплика оператора никогда не суммаризуется; свёртка или пол могут
её забрать только после того, как реестр её процитировал.

### 11. Пары вызовов остаются целыми

Отрезок — замкнутая компонента вызовов инструментов и отвечающих им
результатов; ни один уровень не оставляет вызов без результата или результат
без вызова.

### 12. Повторы остаются воспроизводимыми

Носитель зависит только от сообщений, которые он заменяет: никаких временных
меток и случайно созданных идентификаторов. Одна и та же история даёт одни и
те же запросы — это и позволяет воспроизвести записанный запуск после его
первой компакции.

## Арифметика бюджета

При `O = W × llm_output_max_tokens_ratio`, если провайдер резервирует вывод
внутри окна (`provider_reserves_output_in_context_window`), иначе 0:

```text
T      = min(W × compaction_trigger_ratio,
             W − O − request_context_safety_tokens − W × compaction_trigger_turn_headroom_ratio)
R      = compaction_target_ratio × min(T, P_before)
need   = P + рост реестра − R                    # сколько проходу ещё освободить
span   ≤ compaction_summary_group_max_tokens      # соседние блоки, от старых к новым
отправка при span > max(размер пустой выжимки, compaction_summary_min_unit_tokens)
вход   ≤ min(compaction_summariser_input_max_tokens, W / 4)
бюджет = clamp(span × compaction_summary_ratio,
               compaction_summary_min_output_tokens,
               compaction_summary_max_output_tokens)   # свёртка: compaction_fold_max_output_tokens
провод = 2 × бюджет                               # запас на перерасход; урезание обрежет
реестр = clamp(W × compaction_ledger_ratio,
               compaction_ledger_min_tokens, compaction_ledger_max_tokens)
```

Доли бюджета носителя по разделам: Facts and values 35 %, Progress 25 %,
Decisions and constraints 15 %, Open 15 %, Failures 10 %; неиспользованное
разделом раздаётся в этом же порядке. Доли реестра: указания оператора 30 %,
идентификаторы 30 %, файлы 15 %, открытые пункты 15 %, сбои 10 %,
перераспределение такое же.

Пример: окно 256k, выходной лимит 64k, доля триггера 0,59:
`T = min(151 040, 256 000 − 65 536 − 1 024 − 38 400) = 151 040`,
`R = 90 624`; отрезок в 6 000 токенов сжимается до 1 200 токенов и
отправляется с лимитом 2 400; реестр может занять 5 120 токенов.

## Состояния отказа

| Условие | Что происходит | Где видно |
|---|---|---|
| Суммаризатор бросил исключение (5xx, лимит, сброс) | отрезок остаётся; при нужде пол | `tier2_failures.transport` |
| Суммаризатор не ответил вовремя | вызов брошен; отрезок остаётся | `tier2_failures.timeout` |
| В ответе нет пригодного текста | засчитано против отрезка; отрезок остаётся | `tier2_failures.empty` |
| Запрос больше окна суммаризатора | засчитано против отрезка | `tier2_failures.too_large` |
| Выжимка не меньше отрезка | отброшена | `tier2_failures.not_smaller` |
| Ответ — JSON, незакрытый JSON, без заголовков или обрезан | восстановлен и сохранён | `tier2_recovered.*` |
| Уровни не дотянули до триггера | пол убирает самые старые отрезки | `floor_dropped`, `outcome` |
| Убирать нечего, промпт всё ещё выше триггера | гейт перестаёт открывать проходы | `outcome = at_floor`, затем проходов нет |
| Уровень бросил исключение на полу (проактивно) | уровни с суммаризатором приостановлены на срок | `compaction_exhausted_proactive_suspended` |
| Уровень бросил исключение на полу (после отказа) | лестница выходного лимита; запуск падает, только когда уменьшать некуда | `reactive_413_compaction_exhausted` |
| Хук `pre_compact` отказал | ничего не записано; запуск возвращается в `RUNNING` | `compaction_refused_by_hook` |

## Наблюдаемость

`compaction_completed` несёт, помимо исторических `tokens_before`,
`tokens_after`, `tier1_freed`, `tier2_summarised` и `tier3_folded`:

| Ключ | Значение |
|---|---|
| `outcome` | `below_target`, `below_trigger`, `above_trigger`, `at_floor` или `unchanged` |
| `prompt_before`, `prompt_after` | весь промпт вместе с накладными расходами |
| `trigger_threshold`, `target_tokens` | `T` и `R` прохода |
| `tier1_masked_by_age` | выводы, замаскированные за возраст, а не за размер |
| `tier2_attempted`, `tier2_failures`, `tier2_recovered` | сделанные вызовы, сбои по видам, восстановленные ответы по видам |
| `tier3_failures` | сбои свёртки по видам |
| `floor_dropped`, `floor_reached` | сколько сообщений убрал пол; кончилось ли у него, что убирать |
| `ledger_tokens` | размер пересобранного реестра |

Каждый проход также пишет одну строку `DIAG compaction.pass` с теми же
цифрами, а пол пишет `DIAG compaction.floor`.

## Проверка на конкретном эндпоинте

Носитель зависит от модели, которая его пишет: формат, с которым хорошо
справляется один эндпоинт, может не даться другому. Два стенда в наборе
тестов — та форма, которую стоит прогонять на реальном эндпоинте всякий раз,
когда меняется модель или эндпоинт:

- `tests/_fixtures/compaction/planted.py` — синтетическая сессия агента
  примерно в 150k токенов из шести частей, с пятьюдесятью посаженными
  значениями, четырнадцать из которых оцениваются точным совпадением после
  того, как каждая часть сжата, а выжимки свёрнуты; у двух из четырнадцати
  нет формы, которую мог бы узнать реестр.
- `tests/_fixtures/compaction/long_loop_shape.json` — форма (без содержимого)
  истории долгого цикла в момент, когда его компакция перестала
  продвигаться: 357 сообщений, 153 определения инструментов.

`tests/unit/runtime/test_compaction_contract.py` прогоняет оба стенда с
двойниками суммаризатора, которые справляются, падают, зависают, отвечают
JSON, отвечают незакрытым JSON, не отвечают ничего или ничего не сохраняют;
направьте тот же код на реального провайдера, чтобы его измерить.

## Настройки

| Константа | По умолчанию | Роль |
|---|---|---|
| `compaction_trigger_ratio` | 0,8 | верхняя граница `T` как доли окна |
| `compaction_trigger_turn_headroom_ratio` | 0,15 | запас в один ход ниже потолка приёма |
| `compaction_target_ratio` | 0,6 | куда целится проход, ниже триггера |
| `compaction_emergency_ratio` | 0,95 | проактивная аварийная черта |
| `compaction_keep_recent_turns` | 4 | последние сообщения, сохраняемые дословно |
| `compaction_force_keep_recent_turns` | 1 | то же после отказа провайдера |
| `tool_result_truncation_ratio` | 0,10 | вывод такой доли окна маскируется независимо от возраста |
| `compaction_mask_keep_recent_results` | 8 | выводы, которые никогда не маскируются за возраст |
| `compaction_mask_min_tokens` | 300 | меньшие выводы за возраст не маскируются |
| `compaction_mask_distinct_lines` | 6 | отличительные строки, сохраняемые в заглушке |
